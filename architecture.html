Reactivity pattern

Raw API data is stored in ref([]) (e.g. items, allOrders). Derived values — search results, sorted rows, KPI totals — are computed() properties that re-run automatically when the ref changes. Server-side filtering handles warehouse/category; client-side handles text search and sort order.

Filter System

Four global filters are managed by useFilters() and applied via query params. The backend skips any filter set to 'all'. Inventory does not support the month filter (no time dimension).

Restocking Algorithm
1
Filter: Keep only demand forecasts where forecasted_demand > current_demand (skip stable/declining items)
2
Sort: Increasing trend first, then by demand gap (forecasted − current) descending
3
Greedy fill: For each item, if gap × unit_cost ≤ remaining_budget, include full quantity; else include partial fill to exhaust budget
4
Stop when budget is exhausted. Budget slider is debounced 300ms to avoid excessive API calls.
